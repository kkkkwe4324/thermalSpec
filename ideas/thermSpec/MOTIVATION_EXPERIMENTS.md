# thermSpec 动机实验执行稿（2026-11-13）

**状态：前三个实验方案已确认，待标定、待执行；第四个保留。** 本文是实验执行说明，不代表已获得实验结果。

研究目标：手机承担独立草稿模型，Orin 承担目标模型，根据**信道状态和热状态**联合选择**手机 DVFS 配置与投机长度 K**，改善持续推理性能。本轮 DVFS 动作具体指手机三簇 CPU 的频率上限配置，不代表能够精确锁频。

当前配置：Redmi Note 10 Pro（`chopin`）上的 Qwen2.5-0.5B-Instruct Q4_K_M CPU 草稿模型，以及 Jetson AGX Orin 上的 Qwen2.5-7B-Instruct 目标模型。见 [部署记录](SETUP.md)和[频率接口检查](FREQUENCY_CONTROL_MATRIX_2026-11-08.md)。固定 Orin 配置，本轮不扫描手机 GPU/NPU 频率。

## 二、共用标定与执行口径

### 2.1 提前交付的标定表

执行者先填写 `calibration.md`，保留原始标定日志。表中温度、频率、时长和网络参数均须本机实测，不能直接照搬论文数值。

| 关键变量 | 必须填写的内容 | 判定要求 |
|---|---|---|
| 温度传感器 | CPU `mtktscpu`、电池温度的路径、单位、采样周期、缺失率 | HAL CPU/GPU/NPU 相同值不能算三个独立传感器 |
| **S0：稳定未限频** | CPU/电池温度范围、温升趋势容差、确认时长 | 参考负载下，观察窗口内无热限制，负载中实际频率未因温控下降 |
| **S1：临近限频** | 起始温度范围、温升速度、预热程序、到首次限频的时间范围 | 进入时尚未限频，在参考负载下继续运行会在观察窗口内限频；不要求每个待测 K 都一定触发 |
| **S2：已经限频** | 起始温度范围、温控标志/有效上限、实际频率范围、确认时长 | 必须结合温控状态和负载中实际频率，不能只看温度高低 |
| 首次限频与恢复 | 限频发生时 CPU/电池温度、解除限制的温度和耗时 | 至少重复 3 次预热—恢复，报告范围；升温、降温可能存在滞后 |
| **F低/F中/F高** | 各档小/中/大三簇 CPU 上限，单位 kHz；写入/读回/刷新规则 | 用真实草稿负载验证生效，记录实际频率分布；不能只报一个 GHz 数字 |
| **C好/C差** | 实测 RTT 中位数和高分位数、上下行带宽、抖动、丢包、施加位置 | 第一版只改变 RTT 或带宽之一，另一个固定；运行前后核查实测值 |
| 热状态复位 | 冷却/预热步骤、参考负载、到达状态的判据和容差 | 每个配置独立复位；正式测量时使用相同散热条件，记录辅助预热/散热何时撤除 |
| 测量窗口 H | 实验 2/3 的公共窗口及结束规则 | 覆盖若干完整投机轮，且能观察参考 S1 向 S2 转变；预检后冻结 |
| 持续时长 L | 实验 1 时长 | 尽量覆盖升温、首次限频和限频后一段运行；预检后冻结 |
| 采样/分箱 | 遥测周期、频率采样周期、控制刷新间隔、TPOT 时间分箱 | 可从 1 秒遥测、10 秒 TPOT 分箱开始预检，必要时加密频率采样；检查采集开销，保留未平滑数据 |
| 工作负载 | 提示词清单/顺序、模型/量化版本、线程/绑核、上下文、采样和 stop 规则、输出长度 | 对照保持一致；第一轮可用 Spec-Bench 四类各 2 条、每条最多 128 新 token，持续负载循环相同序列 |
| 运行环境 | Orin 模式/频率/风扇/后台负载；手机电量、充电状态、环境温度、摆放 | 同组对照保持一致，记录 Orin 限频、后台干扰和信道漂移 |

**S0/S1/S2 是状态，不是三个通用温度点。** 应交付“温度范围＋温升趋势＋热限制状态＋实际频率”的判据。S1/S2 温度可能重叠。下述实验控制初始状态，不声称整个窗口温度恒定。

保留原厂温控和既有停止边界。现有短测脚本在电池 38°C、`mtktscpu` 65°C 或 CPU thermal 限制出现时停止，不能直接完成 S2 采集。执行前核对项目运行流程；如现有边界使 S2 不可达，记录“不可达/待解决”，不自行修改停止条件或强行补图。

### 2.2 正式实验的先决检查

1. 冷态检查 `K=0,1,2,4,8` 的正确性和端到端开销。K=0 为 target-only，不运行草稿；K=1 仍有目标验证，不能当普通解码。
2. 同一 greedy 配置下逐 token 核对有效输出；固定缓存状态、prefill 边界和 stop 规则。拒绝的候选 token 不计入有效输出。
3. 分离手机真实计算与 USB/SSH/服务请求开销。现有 4 条短提示词、最多 8 token 的测试中投机路径更慢，尚无加速证据。若长输出仍全部更慢，照实报告并先定位瓶颈。
4. 核对受控信道确实作用于草稿—验证关键路径；仅改变无关连接不算有效信道实验。

### 2.3 指标、重复与日志

- **端到端摊销 TPOT = 解码阶段总墙钟耗时 / 最终有效输出 token 总数。** 包含草稿、通信、验证及必要等待；prefill 单独报告。汇总时先加总耗时和 token，再相除。
- 记录完整请求耗时、prefill、每轮 K、接受草稿数、有效输出数、草稿计算、通信等待、目标验证、其他调度开销。若阶段重叠，不直接相加；跨设备不直接相减未同步时间戳，本地耗时用单调时钟。
- 分开记录**策略请求上限、接口读回、实际频率、热限制/有效上限**。等待时低利用率降频不能当热限频。系统清除频率请求属于控制失效，须标注。
- 每个条件至少 **3 次独立复位后运行**。同一重复编号采用相同任务顺序；候选配置随机化或交错运行，保存顺序。不能把一条运行内的大量 token 当独立重复。
- 实验 2/3 到达 H 后在下一完整解码轮结束时停止测量，记录实际时长和有效 token，不丢弃拒绝候选的耗时。各组任务起点相同，记录处理到的提示词及上下文位置，不挑选有利片段。
- 图片报告独立运行的均值、标准差和原始点；差异接近运行波动时标为“无法区分”，不强行指定唯一最优值。
- 尚无可信手机能耗标定，本轮报告性能与热行为，不能以低温直接声称省电。

## 三、实验 1：持续推理是否产生热退化？

### 实验要求

本实验同时检查热退化是否存在，以及简单固定上限是否有改善空间。

1. 固定 K=4、C好、工作负载和 Orin 配置。比较 F高与 F适中，默认 F适中取 F中；两组都采用固定上限，不混用自动默认策略。
2. 每次从可比 S0 出发，连续执行相同任务序列至 L。正式运行期间不为某一组单独增加散热。
3. 记录温度、温控状态、请求/实际频率、有效输出事件和分段耗时。标记首次热限频时刻及恢复时刻。
4. 每组至少 3 次独立运行，交错顺序。比较全程、预先固定的后半段 TPOT，以及首次限频时间。L 内未限频则记“未观察到”，不记为 0 秒。
5. 若手机限频但端到端 TPOT 未恶化，检查通信或 Orin 是否掩盖了手机变化；不能只凭温度升高宣称端到端热退化。

### 需要提前标定的关键变量

| 必填项 | 本实验要求 |
|---|---|
| S0、限频判据 | 两组起始 CPU/电池温度和趋势在相同容差内，能够识别真实热限制 |
| F高、F适中 | 填写三簇上限与生效证据；F适中由独立预检选定，正式运行后不挑最好的一档替换 |
| C好 | 填写 RTT/带宽和允许波动范围，整段保持固定 |
| L、后半段 | 依据预检确定 L；后半段统一为 L/2 至 L，不按出现有利结果的位置划分 |
| 采样与 TPOT 分箱 | 无有效输出的时间窗标为停顿/缺失，不能画成 0 TPOT |

## 四、实验 2：信道和热状态是否改变最优 K？

### 实验要求

1. 固定同一上限 F固定，默认 F高，扫描 C好/C差 × S0/S1/S2 × K=1–8。共 48 个投机配置，每个至少 3 次，共至少 144 次投机测量。
2. **每个 K 均重新恢复到目标初始热状态**再开始 H 窗口，不能在同一条升温轨迹依次测完 K=1–8。保存窗口内状态转移及限频时间占比。
3. 每个“信道 × 初始热状态”组合补充 target-only 参考，每组至少 3 次。采用相同客户端计时边界和信道设置，记录实际通信流程；不能把完整投机路径与仅 Orin 本地计算时间直接比较。
4. 用独立预检在 C好/S0/F固定 下选择 K冷好，并在正式采集前冻结。对所有状态量化该固定 K 相对本组最佳 K 的损失。预检不并入正式均值。
5. 记录草稿、通信、目标验证耗时和接受率。接受率变化应先检查提示词、上下文差异，不能直接归因于温度。

### 需要提前标定的关键变量

| 必填项 | 本实验要求 |
|---|---|
| S0/S1/S2 | 温度范围、预热方法、状态判据、容差齐全；S2 不可达明确记录，不用任意高温代替 |
| C好/C差 | 明确只变化 RTT 还是带宽，记录两档实测值，采用同一传输实现 |
| F固定 | 预检后冻结；固定的是上限，允许热状态改变实际频率 |
| H | 所有 K 和状态采用同一规则；S1 可以转入 S2，但必须记录 |
| K冷好 | 保存预检选择依据、并列时选择规则；不根据正式结果重新挑选 |
| 任务起点与顺序 | 保存每个重复编号的任务序列和候选 K 运行顺序 |

**图 2a：两面板 TPOT–K 曲线。** 左右分别为 C好、C差；横轴 K=1–8，纵轴端到端 TPOT。每面板三条曲线对应 S0/S1/S2，带误差条；标出最佳 K 和 K冷好，添加 target-only 参考。若 target-only 在三种状态下有差异则分别呈现，不强行合并。

## 五、实验 3：为什么需要联合选择 DVFS 和 K？

### 实验要求

本实验替代旧稿“普通自回归推理选频迁移”的主实验，直接检验两个控制量的联合价值。

1. 四种条件：C好/C差 × S0/S2。冷态指 S0，热态指 S2；S2 不可达则报告缺口，不悄悄换成 S1。
2. 每种条件扫描 F低/F中/F高 × K={1,4,8}，每格至少 3 次独立复位。共 36 个配置、至少 108 次测量；沿用公共 H、工作负载、计时和复位规则。
3. 在独立预检的 C好/S0 网格中，按最小端到端 TPOT 选出参考组合 `(F参考,K参考)`，保存并列选择规则并冻结。两者必须来自本实验候选集，预检数据不并入正式均值。
4. 对每种正式条件，用相同完整网格计算下列参考性能，不挑选有利运行。

| 对比项 | 固定/选择规则 | 说明 |
|---|---|---|
| 全固定参考 | 使用 `(F参考,K参考)` | 模拟在基准条件调好后保持不变 |
| 只选 K | 固定 F参考，在三个 K 中选择本条件最佳 | 单独调整投机长度的空间 |
| 只选 DVFS | 固定 K参考，在三档 F 中选择本条件最佳 | 单独调整频率上限的空间 |
| 联合选择参考 | 在九个 `(F,K)` 中选择本条件最佳 | 当前候选网格内的联合空间 |

5. 上述“最佳”均为事后网格参考，不是在线方法成绩。联合选择搜索范围更大，本来就不会更差；关键是收益幅度、重复稳定性，以及最佳 F 是否随 K 改变、最佳组合是否随信道/热状态迁移。
6. 记录各格实际频率、限频占比及分段耗时。如果 S2 下三档上限都被压到相同实际频率，说明动作失去区分度，不能据此直接说 DVFS 不重要。

### 需要提前标定的关键变量

| 必填项 | 本实验要求 |
|---|---|
| S0/S2、C好/C差 | 沿用实验 2 定义，不自行改变温度判据或网络档位 |
| 三档 F | 三簇上限、生效证据齐全；核查热态下实际频率是否仍有区分 |
| F参考、K参考 | 来自独立冷态好信道预检，正式测量后不得更换为使单变量方案更差的配置 |
| H、网格顺序 | 统一窗口，每格重新复位；随机/交错测试，不按频率升序连续升温测量 |
| 优化目标 | 全部最小化端到端 TPOT，不能单变量优化功耗、联合方案优化速度 |

### 最后交付的图片

**图 3a：四张上限–K 热力图。** 四面板分别为 C好/S0、C好/S2、C差/S0、C差/S2；横轴 K={1,4,8}，纵轴 F低/F中/F高。统一色标，格内标注 TPOT；每列标出最佳 F，并标出网格最佳组合。无法区分的候选同时标注，误差与实际频率放附表。
